# The contract

Source of truth: `crates/core/src/types.rs`. This page explains it. If they disagree, the code wins; tell ENGINE.
Only ENGINE changes the contract (see `AGENTS.md`, "Asking another owner").

## 1. How each face reaches the engine

Everything crosses boundaries as **JSON strings**. Same shapes everywhere.

| Face | How | Types |
|---|---|---|
| Web | `crates/core-wasm` via wasm-pack: `assess(json)`, `registry()`, `demo()`, `score(crew, json)` | `apps/web/src/contract/*.ts` (generated by ts-rs, committed) |
| egui | depends on `ahc-core` directly: `ahc_core::assess(&AssessInput)` | Rust |
| API | depends on `ahc-core` directly | Rust |
| Mobile | `crates/core-ffi` with flutter_rust_bridge, wrapping `ahc_core::assess_json` | Dart, generated |

Regenerate the TypeScript types: `cargo test -p ahc-core` (writes `apps/web/src/contract/`). CI fails if they are stale.

## 2. Vocabulary (enums, serialised snake_case)

- `Status`: `unknown < nominal < watch < caution < urgent`. Ordered; the worst wins.
- `Escalation`: `monitor`, `self_care`, `consult_ground`, `urgent`.
- `Environment`: `station`, `transit`, `lunar_base`, `mars_base`, `earth_clinic`.
- `Hazard`: `radiation`, `isolation`, `distance`, `gravity`, `closed_environment`.
- `Region`: `head eyes heart lungs bones muscles gut immune skin mind`.
- `Confidence`: `low medium high`. `SourceStatus`: `sourced adapted placeholder`.

UI mapping (do this in the UI, it is presentation only):

| Status | Colour | Icon | Word |
|---|---|---|---|
| nominal | green | ● | Nominal |
| watch | blue | ◐ | Watch |
| caution | amber | ▲ | Caution |
| urgent | red | ◆ | Urgent |
| unknown | grey | ○ | Unknown |

## 3. Events (the append-only log)

```jsonc
{
  "id": "uuid",              // unique
  "crew_id": "cdr",          // whose log this belongs to
  "met_s": 12355920,         // mission elapsed seconds
  "earth_ms": 1792627920000, // unix ms
  "environment": "transit",  // at the time of the event, never rewritten
  "author": "cdr",           // crew id, "ground:<name>" or "device:<name>"
  "kind": { "type": "reading", "indicator_id": "heart_rate", "value": 71.3, "device": "chest strap", "confidence": "high" }
}
```

`kind.type` is one of:

| type | fields | notes |
|---|---|---|
| `reading` | `indicator_id, value, device, confidence` | value in the indicator's canonical `unit`. Convert before logging. Camera pulse = `confidence: "low"` |
| `baseline` | `indicator_id, value` | preflight baseline |
| `symptom` | `text, region?` | |
| `check_in` | `mood, stress, energy, sleep_quality, note?` | each 1 (bad) to 5 (good) |
| `kit_use` | `item, qty` | decrements the kit |
| `action_taken` | `action_id, indicator_id` | |
| `report_sent` | `report_id, deliver_at_earth_ms` | |
| `ground_note` | `text, sent_earth_ms, in_reply_to?` | written with `author: "ground:..."` |
| `override` | `indicator_id, bands, reason` | flight surgeon changes a threshold |

Rules: never edit or delete an event. To correct something, append a new event.

## 4. Engine

`assess(AssessInput) -> Assessment`. Pure function. No clock, no I/O, no randomness.

```jsonc
// AssessInput
{ "crew_id": "cdr", "events": [/* Event */], "now_met_s": 12377520, "kit": [{ "item": "cold_pack", "qty": 2 }], "registry": null }

// Assessment
{
  "overall": "watch",
  "escalation": "monitor",
  "indicators": [{ "indicator_id": "heart_rate", "status": "watch", "value": 71.3, "last_met_s": 12373200,
                   "confidence": "high", "baseline": 63.1, "preflight": 60, "drift_pct": 13.0,
                   "reason": "+13% from your in-flight baseline.", "bands": { /* Bands */ }, "source_status": "placeholder" }],
  "regions": [{ "region": "heart", "status": "watch" }],          // always all 10 regions
  "flags": [{ "indicator_id": "heart_rate", "status": "watch", "escalation": "monitor",
              "summary": "Resting heart rate: +13% from your in-flight baseline.",
              "next_step": "Recheck at your next routine slot.",
              "actions": [{ "action": { "id": "hr_hydrate", "text": "...", "kit_item": "electrolyte_drink" }, "available": true }] }],
  "kit": [/* remaining after kit_use events */]
}
```

How status is decided, per indicator, using the **latest** reading:

1. No reading: `unknown`.
2. Older than `stale_after_h`: `unknown` ("Stale").
3. Latest reading has `confidence: low`: `unknown` ("confirm with a proper device"). Low-confidence readings never flag and never enter the baseline.
4. Outside the caution band: `urgent`.
5. Outside the nominal band: `caution`.
6. Inside nominal but more than `watch_drift_pct` away from the in-flight baseline (mean of earlier trusted readings, needs 5 or more), or else from the preflight baseline: `watch`.
7. Otherwise `nominal`.

Bands come from, in order: the latest `override` event, the range for **the environment stored on the reading**, the default range.

Escalation: `urgent` status gives `urgent`. `caution` gives `self_care`, or `consult_ground` once two trusted readings in a row are out of range. Everything else `monitor`.

Flags: every indicator at `watch` or worse, worst first. Show the top one or two.

## 5. Registry

`crates/core/registry.json`: one record per indicator (`Indicator` type). It carries the texts the UI shows: `what`, `why_in_space`, `how_to_measure`, `expected_change`, `source`, `actions`, `hazards`, `region`, `alt_units`.
Guided measurement cards, region detail, the library and the hazard lens all read from it. Do not copy these texts into the UI.

Current ids: `heart_rate bp_systolic bp_diastolic body_temp blood_glucose spo2 sleep_hours mood stress radiation_dose`.
All ranges are currently `placeholder`. Task `ENGINE-6` sources them.

Unit conversion: `display = canonical * factor + offset` from `alt_units`. Log canonical.

## 6. Gamification

`score(crew_id, events) -> Score { crew_id, xp, level, streak_days }`.
It runs on `Activity { crew_id, met_s, kind }`, a projection that has **no value field**. The leaderboard and crew views may only ever receive `Activity` or `Score`, never `Event`.
XP: measurement, check-in, report sent = 10; follow-up action = 15; symptom reported = 30 (early-report bonus). Streak is in mission days.

## 7. Demo seed

`demo()` returns `{ crew_id: "cdr", now_met_s, launch_earth_ms, events, kit }`: Mars transit, mission day 143, 06:12, 15 days of history. Opening state (asserted by tests in `crates/core/src/lib.rs`):

- heart rate `watch` (creeping up), sleep `watch`, mood and stress `watch`
- blood pressure and glucose `unknown` (stale: this is why the scheduler prompts a BP check)
- overall `watch`, escalation `monitor`
- then: log `bp_systolic` 138 → `caution` / `self_care`; a second high reading → `consult_ground`

## 8. Browser storage (web and the egui WASM build share an origin)

| localStorage key | Content |
|---|---|
| `ahc.events.v1` | JSON `Event[]`, append-only. Empty on first load: seed from `demo().events` |
| `ahc.settings.v1` | `{ crew_id, environment, one_way_delay_s, role, ai_enabled, met_offset_s }` |
| `ahc.outbox.v1` | reports waiting for the API |

Append with read-modify-write of the whole array, and listen to the `storage` event so the other tab or the safe-mode console updates live. Native egui uses a JSON file with the same `Event[]` shape.

## 9. Ground Station HTTP API (`crates/api`, axum)

Base `/api`. JSON. CORS open. The astronaut side must work when this is unreachable.

| Method | Path | Auth | Body / result |
|---|---|---|---|
| GET | `/api/health` | none | `{ "ok": true }` |
| POST | `/api/reports` | none | body `Report`; server stores it; 201 |
| GET | `/api/reports` | basic | `Report[]` whose `deliver_at_earth_ms <= server now` (the delay is enforced here) |
| POST | `/api/notes` | basic | `{ crew_id, text, in_reply_to?, delay_s }`; server stamps `sent_earth_ms` and delivery time |
| GET | `/api/notes?crew_id=cdr` | none | delivered notes as `Event[]` with `kind.type = "ground_note"`; the crew app appends new ones to its log |

`Report` and `Sbar` are **not in the contract yet**: task `ENGINE-2` adds them, proposed shape:

```jsonc
{ "id": "uuid", "crew_id": "cdr", "sent_met_s": 0, "sent_earth_ms": 0, "deliver_at_earth_ms": 0,
  "sbar": { "situation": "", "background": "", "assessment": "", "recommendation": "" },
  "assessment": { /* Assessment at send time */ },
  "events": [ /* the last 48 h of events for context */ ] }
```

`draft_sbar(assessment, registry) -> Sbar` lives in core and is deterministic. The AI may only rephrase it.
Delay is two-way: reports are held on the way down, notes on the way up. Demo default `one_way_delay_s = 20`, shown in the UI as "18 min (compressed for demo)".
